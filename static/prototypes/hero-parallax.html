Where this is served
  • Live (Netlify): /prototypes/hero-parallax.html on the deployed site.
  • Local dev: npm run dev → http://localhost:5173/prototypes/hero-parallax.html
  • Don't double-click to open from disk — browsers block WebGL texture uploads from file:// URLs.
How this works
  • Two textures: the photo and a grayscale depth map (white = close, black = far) generated by Depth-Anything-V2 via Immersity.
  • Fragment shader samples the depth at each pixel and offsets the photo's UV coordinates by mouse × depth × strength. Closer pixels shift more, far pixels shift less — fake 3D.
  • Mouse position lerps toward the actual cursor each frame for organic motion (the "smoothing" slider).
  • On touch devices the browser's DeviceOrientation event drives the same parameter (tilt = mouse).
  • Honours prefers-reduced-motion: if you've turned it on at the OS level, the image is static.
  • If WebGL isn't available, the photo just shows static. Same outcome as the live site.
What would change in the real site
  • HeroSection.svelte swaps its <img> for a <canvas> with this shader, and accepts an optional depthImage prop.
  • If depthImage is missing or fails to load, falls back to the existing <img>. So no risk to other hero usages.
  • Each homepage hero photo would need its depth map generated once — same workflow you just used (Immersity → download greyscale PNG).
  • Cost: ~80 KB extra over the existing photo for the depth map. Small.
